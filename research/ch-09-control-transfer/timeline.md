# Chapter 9 chronology

This chronology separates mathematical machines, notation, working hardware,
published architecture, programming method, and processor implementation.

| Date | Development | Relevance and caution |
|---|---|---|
| 1936--1937 | Turing publishes machines whose next configuration depends on state and scanned symbol | Mathematical control transition, not a stored-program instruction set |
| 1940s | Electronic machines use conditional orders and repeated instruction sequences | Exact conventions and working dates require machine-specific primary sources |
| 1947 | Goldstine and von Neumann publish flow diagrams and induction assertions for coding | Early systematic program reasoning; distinguish report from later terminology |
| late 1940s--1950s | Stored links and subroutine conventions develop on early machines | Open primary EDSAC sources before priority claims |
| 1964 | System/360 publishes a compatible control-transfer architecture | Target and condition rules become long-lived software promises |
| 1966--1969 | Structured-control and axiomatic-programming papers sharpen control and proof methods | Mathematical expressiveness, style advice, and proof rules are different claims |
| 1970s--1980s | Pipeline and branch-prediction research makes path choice an implementation cost | Architectural next state remains distinct from speculative work |
| 1980s--present | RISC and x86 lineages retain different predicate, target, and link shapes | Compare exact forms rather than RISC/CISC labels |
| 2000s--present | CFI, shadow stacks, and profile-guided layout add policy and economic layers | Mechanisms enforce selected contracts, not universal control correctness |
| 2026 | Current ISA and protection manuals pin practical claims | Extensions, processor advice, and tool behavior are versioned |
